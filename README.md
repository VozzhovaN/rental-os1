# Rental OS

**Rental OS** — CRM-система для управления арендой недвижимости: посуточная (краткосрочная)
и долгосрочная аренда, продажа объектов, работа с собственниками, финансовый учёт,
клиентские презентации и интеграции с площадками (Авито, ЦИАН, Домклик).

Система рассчитана на одного оператора/агентство (single-tenant): все авторизованные
сотрудники работают с общими данными.

## Возможности

| Модуль | Что делает |
| --- | --- |
| **Dashboard** | Сводка по загрузке, ближайшим заездам/выездам, календарь занятости. |

| **Презентации** | Клиентские подборки объектов с публичной ссылкой и выгрузкой в PDF. |
| **Финансы** | Единый реестр операций, доход/расход, комиссии, расходы, отчёты по объектам. |
| **Настройки / Интеграции** | Честный статус подключения площадок, XML-фиды ЦИАН, OAuth Авито, журнал синхронизации. |

## Технологический стек

- **Next.js 16** (App Router) + **React 19**
- **Prisma 6** + **SQLite** (файловая БД для разработки/демо)
- **TypeScript**, **Tailwind CSS 4**
- Аутентификация: **Argon2id**, серверные сессии (хэш токена в БД)
- Обработка фото: **sharp**; PDF: **pdfkit**
- Валидация: **Zod**

## Быстрый старт

### Требования

- Node.js 20+
- npm

### Установка и запуск (разработка)

```bash
# 1. Установить зависимости
npm install

# 2. Создать файл окружения из примера и заполнить значения
copy .env.example .env      # Windows PowerShell: Copy-Item .env.example .env

# 3. Применить схему БД
npx prisma migrate deploy
# или для разработки:
npx prisma migrate dev

# 4. Сгенерировать Prisma Client (обычно выполняется автоматически)
npx prisma generate

# 5. Загрузить демонстрационные данные (по желанию)
npm run prisma:seed

# 6. Запустить сервер разработки
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). CRM доступна по адресу `/crm`
(при отсутствии сессии откроется страница входа `/login`).

### Продакшн-сборка

```bash
npm run build
npm run start
```

> В продакшне обязательны переменные окружения `SESSION_SECRET`,
> `INTEGRATION_ENCRYPTION_KEY`, `APP_ORIGIN`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`
> (см. ниже). Без них приложение намеренно не запустится или откажет в работе
> критичных функций (fail-closed). Подробности — в
> [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) и
> [`docs/PRODUCTION_CHECKLIST.md`](docs/PRODUCTION_CHECKLIST.md).

## Переменные окружения

Полный список — в [`.env.example`](.env.example).

| Переменная | Обязательна | Секрет | Назначение |
| --- | --- | --- | --- |
| `DATABASE_URL` | ✅ | нет | Путь к БД, напр. `file:./dev.db`. Не хардкодится в коде. |
| `SESSION_SECRET` | ✅ (prod) | **да** | «Перец» для хэша сессионных токенов, ≥ 32 символов в проде. |
| `INTEGRATION_ENCRYPTION_KEY` | ✅ (prod) | **да** | Ключ AES-256-GCM для шифрования токенов интеграций, ≥ 32 символов. |
| `APP_ORIGIN` | ✅ (prod) | нет | Канонический origin (`https://…`) для защиты от CSRF. |
| `ADMIN_EMAIL` | ✅ (bootstrap) | нет | E-mail первого администратора. |
| `ADMIN_PASSWORD` | ✅ (bootstrap) | **да** | Пароль администратора, ≥ 12 символов. Задаётся только в окружении. |
| `SESSION_TTL_DAYS` | нет | нет | Время жизни сессии в днях (по умолчанию 7). |
| `CIAN_ACCESS_KEY`, `CIAN_FEED_BASE_URL`, `CIAN_ACCOUNT_ID` | нет | часть — да | Публикация ЦИАН. |
| `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET` | нет | **да** | OAuth Авито. |
| `DEMO_MODE` | нет | нет | Режим демонстрации: баннер + защита команды сброса демо. Не ослабляет безопасность. |
| `PHOTO_STORAGE_ROOT` | нет | нет | Каталог хранения загруженных фото (по умолчанию `<cwd>/storage`). |


## Первый вход

Учётная запись администратора создаётся автоматически при старте/сидинге из
переменных `ADMIN_EMAIL` и `ADMIN_PASSWORD` (механизм bootstrap). Существующий
пароль не перезаписывается.

1. Задайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`.
2. Выполните `npm run prisma:seed` (или запустите приложение — bootstrap отработает).
3. Откройте `/login` и войдите указанными данными.

Ролей/RBAC нет: администратор имеет полный доступ ко всем разделам.

## Руководство по разделам CRM

Навигация — в левом меню. Ниже — назначение каждого раздела и типовые сценарии.

### Dashboard (`/crm/dashboard`)
Стартовый экран. Показывает сводную загрузку, ближайшие заезды и выезды, а также
календарь занятости объектов (занятые интервалы, свободные даты, будущие брони).

### Объекты (`/crm/properties`)
Карточки недвижимости.
- **Создать:** «Добавить объект» → параметры (тип, адрес, площадь, комнаты, гости),
  цены (посуточно/помесячно), тип управления:
  - **OWN (свой)** — доход полностью ваш.
  - **COMMISSION (комиссия)** — объект принадлежит собственнику; указываются проценты
    комиссии и способ сбора аренды (оператор / собственник напрямую).
- **Фотографии:** загрузка изображений (JPEG/PNG/WEBP) с проверкой содержимого;
  первая фотография становится обложкой; до 10 файлов за раз, до 60 на объект.
- **Статусы:** ACTIVE / INACTIVE / ARCHIVED.

### Гости (`/crm/guests`)
База гостей краткосрочной аренды: имя, телефон, e-mail, мессенджер (MAX/Telegram),
комментарии и **история** (обращения, брони, заезды/выезды). История ведётся
автоматически при действиях с бронями.

### Бронирования (`/crm/bookings`)
Управление бронями.
- **Создать бронь:** объект, гость, канал продаж, даты заезда/выезда, сумма, число гостей.
- **Жизненный цикл (FSM):** `PENDING → CONFIRMED → COMPLETED`, а также `CANCELLED`.
  Статусы `COMPLETED` и `CANCELLED` — терминальные.
- **Заезд/выезд:** действие «Выезд» доступно только из статуса `CONFIRMED`.
- **Финансы брони:** приём оплат, частичные оплаты, возвраты (refund). По отменённой
  брони новую оплату принять нельзя. Комиссия фиксируется снимком при первой финоперации.

### Собственники (`/crm/finance/owners`)
Собственники комиссионных объектов.
- Карточка собственника, привязанные объекты.
- **Выплаты (payouts)** с распределением по объектам.
- **Сверки (settlements)** за период: итоги всегда рассчитываются из фактов реестра.

### Долгосрочная аренда (`/crm/long-term`)
Два независимых слоя:
- **Объявления (listings)** — маркетинговая карточка (цена, депозит, условия, тексты),
  статусы DRAFT / ACTIVE / PAUSED / ARCHIVED; используются для публикации (напр. ЦИАН).
- **Договоры (contracts)** — реальная аренда: помесячная ставка, депозит, день оплаты.
  Формируются **начисления (charges)**, принимаются **платежи**, платёж распределяется
  по начислениям (allocations). Цена договора — снимок, не синхронизируется с объявлением.

### Продажи (`/crm/sales`)
Контур продажи объектов (отдельный от аренды).
- **Объекты продажи (`/crm/sales/properties`)** — карточка SaleListing: цена, описание,
  контакты для публикации, статусы DRAFT / ACTIVE / PAUSED / SOLD / ARCHIVED.
- **Клиенты (`/crm/sales/clients`)** — покупатели (Buyer) и их **интересы** к объектам.
  По интересу ведутся **показы (viewings)** и **задатки (deposits)** со своими статусами.
- История покупателя ведётся автоматически (append-only).

### Презентации (`/crm/presentations`)
Клиентские подборки объектов.
- Создание подборки из 1–5 объектов, разделы и фотографии.
- Статусы DRAFT / READY / PUBLISHED / ARCHIVED.
- **Публичная ссылка** `/p/{token}` доступна только для READY/PUBLISHED; токен —
  криптографически случайный. Есть выгрузка в **PDF**. Внутренние заметки на публичной
  версии не показываются.

### Финансы (`/crm/finance`)
Единый финансовый контур на основе неизменяемого реестра операций (FinancialTransaction).
Подразделы:
- **Обзор** — сводные показатели.
- **Объекты** — экономика по каждому объекту (валовая аренда, доход бизнеса, расходы, прибыль).
- **Операции** — список финансовых операций.
- **Комиссии** — комиссии оператора и поступления от собственников.
- **Расходы** — ручные расходы (уборка, стирка, коммуналка, реклама и т. п.).
- **Отчёты** — сводные отчёты за период.

Суммы хранятся в целых рублях. Идемпотентность операций обеспечивается ключом источника
(`sourceKey`).

### Настройки / Интеграции (`/crm/settings`)
- **Общие** — настройки CRM.
- **Интеграции** — статус подключения площадок. Статусы отображаются **честно**: система
  не показывает ложный «Подключено» и фиктивные галочки.
  - **Авито** — подключение через OAuth (при наличии реальных ключей).
  - **ЦИАН** — публикация через XML-фиды (`/api/feeds/cian/…`).
  - **Домклик** — ограничение провайдера отражено явно.
- **Журнал синхронизации** — лог операций с фильтрами; секреты в логах маскируются.

> Каналы продаж (SalesChannel) — это не то же самое, что реальное подключение площадки.
> Канал можно указывать в бронях без реальной интеграции.

## Ключевые бизнес-правила

- **Занятость (occupancy):** объект считается занятым только бронями в статусах
  `PENDING` и `CONFIRMED`. `COMPLETED` **не** блокирует будущие даты.
- **FSM брони:** `PENDING → CONFIRMED → COMPLETED`; `CANCELLED` — из активных статусов.
  Выезд — только из `CONFIRMED`.
- **Финансы:** реестр неизменяемый; операции идемпотентны по `sourceKey`; суммы — целые рубли.
- **Долгосрочная аренда:** объявление и договор — разные сущности; цена договора — снимок.
- **Экономика объекта:** для OWN и COMMISSION считается по разным правилам; учитывается
  способ сбора аренды (оператор / собственник напрямую).

Эти инварианты закреплены тестами; изменять бизнес-логику без обновления тестов не следует.

## Демо-версия для защиты проекта

Для демонстрации предусмотрена отдельная безопасная демо-конфигурация:
- Все данные **искусственные** (нет реальных гостей, собственников, покупателей, ключей площадок).
- Работает с той же моделью безопасности, что и продакшн (`NODE_ENV=production`);
  `DEMO_MODE=true` лишь включает баннер и защищённую команду сброса.

Локальный запуск демо на **отдельной** БД (не `dev.db`):

```powershell
$env:DATABASE_URL="file:./demo.db"; $env:DEMO_MODE="true"
npx prisma migrate deploy
npm run demo:seed
npm run build; npm run start
```

Сброс демо-данных выполняет только оператор командой `npm run demo:reset`
(fail-closed: работает лишь при `DEMO_MODE=true` и БД с именем, содержащим `demo`;
никогда не трогает `dev.db` или продакшн-подобную БД). Публичного эндпоинта сброса нет.

Пароль демо-доступа не хранится в репозитории и передаётся отдельно. Полная инструкция —
[`docs/COURSE_DEMO_DEPLOYMENT.md`](docs/COURSE_DEMO_DEPLOYMENT.md).

## Безопасность

- Пароли — Argon2id; серверные сессии (в БД только хэш токена).
- Cookie: `HttpOnly`, `Secure` (prod), `SameSite=Lax`.
- Защита CSRF по `Origin`/`Referer` + `APP_ORIGIN` (в проде — fail-closed).
- Токены интеграций шифруются AES-256-GCM; секреты маскируются в логах; в клиент не попадают.
- Заголовки безопасности и CSP; загрузка фото проверяется по содержимому; защита от path traversal.
- Каждый API-маршрут классифицирован (по умолчанию — требует аутентификации).

Подробности и план реагирования на инциденты — в [`docs/SECURITY.md`](docs/SECURITY.md).
